## Why this note

Once a year we agree which technologies we push to customers, which we experiment with, and which we deliberately avoid. This radar is for presales and architecture choices in 2026. It uses the usual four rings: **Adopt**, **Trial**, **Assess**, **Hold**. Comments welcome until 2026-03-20; after that it goes into the proposal template.

## Adopt

**Microsoft Foundry**
Our default platform for new generative AI work. One project and governance model for models, agents, evaluations and tracing makes it easier to hand over to customer IT teams. Model deployments, content safety and evaluation runs live in one place, which shortens the security conversation (see the lesson from last year: the security officer reviews the design in sprint 1).

**Foundry IQ**
Adopt for knowledge retrieval over enterprise content. Knowledge bases with agentic retrieval give us query planning over multiple sources and answers with citations without building our own orchestration layer each time. We are using it on the Clinical Knowledge Assistant, where answers must be grounded on clinical guidelines, and on the Asset Management Agent, where it sits next to agent tools built on Foundry Agent Service. Both are early, but the developer experience is clearly better than our hand-rolled retrieval pipelines of 2024 and 2025.

Guidance:
- Treat source content governance as part of the project: versioning, owners, archiving of old documents.
- Respect source permissions from day one.
- Build an evaluation set with the customer before the first demo.

## Trial

**Knowledge graphs for retrieval**
Several questions customers ask are not answered by a single passage: "who worked on what", "which assets are linked to which incidents", "what changed since last year". Plain vector retrieval struggles with these. We want to trial entity and topic graphs alongside Foundry IQ knowledge bases, starting with an internal experiment on our own project documents, and measure against plain RAG on a fixed question set. Owner: Pieter, with Ruben for the tooling. Decision on moving to Adopt in Q4.

**Agent frameworks with tool calling**
Trial on customer work where agents act on structured systems, with strict tool permissions and logging.

## Assess

- Computer-use style agents for legacy UIs: interesting, not yet robust enough for customer production.
- Small language models on the edge for industrial customers: watch, no project yet.

## Hold

**Fine-tuning of LLMs**
Hold. In almost every case we looked at, better retrieval, better prompts and a proper evaluation set beat fine-tuning on cost, time and maintainability. Fine-tuned models also complicate model upgrades and make it harder for customers to own the solution. We make an exception only for narrow classification or extraction tasks where a classic ML model or a custom extraction model is the better tool anyway, and that is not LLM fine-tuning.

**Self-hosted vector databases**
Hold for customer projects. Managed search covers our needs; running our own adds operational burden that our customers do not want.

## Housekeeping

- Every new AI project gets an evaluation set and a cost dashboard in sprint 1.
